## Adjustments to the original plan (and why)
1. **Heartbeat.** A plain script cannot type into a Claude session. So the Scheduler session starts a standalone wall-clock script (`heartbeat.py`, polls the clock, `next = now + 5h05m`, recalculated after each trigger) that writes a timestamped trigger file + log and shows a Windows notice; **and** an app scheduled task (runs outside any session's tokens) that every 5 h reads that state and sends a "check for stall and resume" message to both main and Testing. Together they are token-independent.
2. **Measurable pass criteria** (instead of "near-perfect"):
   - *Map alignment:* every camera linked through the page; where truth calibration exists, median floor error of each camera vs truth ≤ 0.30 m and same-spot disagreement between cameras ≤ 0.40 m; where no truth exists, the page's own cross-camera agreement line must be "good" and references/areas drawn line up visually in every camera.
   - *Occlusion:* during occlusion events listed for the scenario, the people count on the map stays within ±1 of the truth/visible count and no two people merge for > 2 s.
   - *ID persistence:* map-ID switches per real person ≤ 1 over the whole clip (ID fragmentation ratio = map IDs / real people ≤ 1.5 for the clip), and the same map number is shown in every camera that sees that person.
   These thresholds can be tightened later; they are recorded with every result.
3. **No cheating.** Tests use only things a user can do on the page (click, drag, type, buttons, load video). Truth data is used **only to score** results, never to place points. Corners are found by looking at the picture (visual identification) or by the page's auto-corner tool.
   - *User clarification 2026-11-15:* testers need not click physically. They may call, from the console or a script, the same page functions a button, input or drag triggers (e.g. set an input's value and fire its handler, call the tune/accept action). This is allowed only for functions a user can reach through the UI, with values the tester read by eye from frames. Not allowed: truth data, internal state the UI doesn't expose, or editing fits directly.
4. **Scenario sources.** Public multi-camera datasets with ≥2 synchronised views and >1 person (EPFL multi-camera pedestrians: lab, terrace, passageway, campus; plus others Finding Video finds). Overlap cases may be made by cropping views of one dataset (as done for EPFL ก/ข/ค), which is honest because the page only sees the crop.
5. **Skills.** Only skills already installed and verifiable are adopted; unverified third-party downloads are skipped and recorded with reasons in `SKILLS_EVAL.md`.
